# Direct-device V1: Venice routing and Surplus media

Goal: the StickS3 uses the phone hotspot to call Venice for decisions and Surplus for transcription and media generation, without a VPS. **Incomplete and not ready to flash.** The default `StickS3/` build still requires the bridge and must not be represented as the direct version. Keep it intact as a fallback until direct paths pass tests.

An isolated music submission journal is being developed in [`direct/`](../direct/README.md); it is not integrated into the existing firmware and must not be treated as direct-device support.

1. Provision separately scoped Surplus and Venice API keys on the device via the setup flow, not in source code. Store in NVS; document that physical access or unencrypted flash may expose it. Use HTTPS with the correct verified CA, a configurable model allowlist, and avoid secrets in logs and URLs. Budget limits must be enforced at the account/key where available; a local counter is only advisory.
2. Upload bounded 16 kHz WAV microphone audio as multipart to `/v1/audio/transcriptions`; account for content-length, timeouts and limited memory. The documented route is file transcription; do not promise Gemini Live interim results without a separately verified streaming API.
3. Classify the transcript as `image`, `song`, `speech`, or `clarify` using the lowest estimated-cost eligible Venice decision model from the account-specific catalog (JEV format), falling back safely if none meets capability or price constraints; account for beta access, provider errors, and calibrated thresholds validated on held-out data. On errors or low confidence, ask for clarification rather than silently start an expensive generation. Do not mistake a classifier's label for a response or image prompt.
4. Call chat as needed to draft/rewrite speech or media prompts; call native Surplus speech, image, and async music APIs. Support explicit provider output formats, bounded memory, partial/chunked HTTP responses, async polling, artifact authentication and redirects without forwarding credentials cross-origin. Preserve cancellation behavior and disclose that a submitted job may still be billed. No retry of ambiguous paid submissions without documented idempotency.
5. Decode media using bounded buffers, handle 135×240 color images and half-duplex StickS3 speaker audio, and release temporary buffers. Handle unsupported formats, oversized assets and network disconnects visibly. Compare peak PSRAM and stack use with Wi-Fi/TLS active. Compile with pinned dependencies and exercise simulated provider responses, then test transcription, all media modes, power, Wi-Fi, failures and billing on the actual stick.
6. Compare fixed rules, a normal generative router, and Venice decision models (including Jev and Clef) using the same held-out synthetic tasks. Record intent accuracy, confusion matrix, confidence calibration, latency, refusals, task success and actual total cost (routing plus follow-on calls); do not infer a cost or quality win from model name or discount.

## Local inference

The StickS3 has 8 MB PSRAM and 8 MB flash shared with firmware, Wi-Fi, TLS, audio and image buffers. Tiny task-specific models such as ESP-SR WakeNet or fixed command classifiers may be practical after measuring real memory, CPU, false activations, battery and audio half-duplex interactions; they are not general transcription or a general-purpose LLM. Many open decision models are far too large for these limits. Existing V1 scope should prioritize direct calls and push-to-talk; local wake word is an experiment, not a promised capability. See https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/wake_word_engine/README.html.

## Course techniques for this device

- Keep a consistent character sheet and, where a selected image-editing API supports it, a reference image. Fixed seeds alone do not preserve character identity across scenes. Preserve a chosen voice where the TTS provider supports it. [Consistency lesson](https://github.com/DataTalksClub/production-ai-agents-for-media-generation/blob/main/01-consistent-media-generation-on-serverless-gpus/01b-consistency.md).
- Treat music generation as a long-running submit/poll job. Persist job IDs before polling; after reconnect reconcile job status before another submission, so a disconnect does not accidentally create a second paid job. [Long-running tools lesson](https://github.com/DataTalksClub/production-ai-agents-for-media-generation/blob/main/02-multi-agent-media-workflows/04-long-running-tools.md).
- Validate format, duration and dimensions before any optional model-based review; cap generation/review attempts and use caregiver review for child-facing content. A judge is an experiment, not a safety guarantee. [Judge loop](https://github.com/DataTalksClub/production-ai-agents-for-media-generation/blob/main/02-multi-agent-media-workflows/05-judge-loop.md).
- Report total decision + transcription + generation spend per accepted artifact, including failures and retries, latency, reference prices, and DIEM utilization; compare equal tasks and quality with the original Gemini. [Cost lesson](https://github.com/DataTalksClub/production-ai-agents-for-media-generation/blob/main/01-consistent-media-generation-on-serverless-gpus/05-measuring-costs.md).
